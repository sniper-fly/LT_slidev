# HeartGarden LT 章立て (Step 3-B 成果物)

5 分 LT、想定枚数 12 枚。Step 3-C でこの章立てに沿って `slides.md` を実装する。

## 最重要メッセージ

AI コーディング時代の手放し運用には、**コンテナ分離だけでは足りない**。
**権限と秘密情報の分離** + **入口/出口の監査** を組み合わせれば、サンドボックスは速度と安全性を両立できる。

## ストーリー軸

タイトル → 自己紹介 → 痛み (都度承認 / dangerously) → コンテナで囲んでも痛みあり → コンテナの本質的限界 (実害シナリオ) → トレードオフ図で「右上が空いている」 → そこで HeartGarden を作りました → 使い方 → 5 つの機能 → アーキ全体図 → まとめ + 記事誘導

## スライド構造

各スライドは以下の 4 要素で記述する。

- **スライドタイトル**: 画面上部に大きく出す一言キャッチ (8〜15 字)
- **メッセージ**: そのスライドで聴衆に持ち帰ってほしい結論 (1 文)
- **内容**: スライド本文に出す要素 (箇条書き or 図解の中身)
- **口頭補足**: スライドには書かず話で添える情報
- **ビジュアル**: 図解・画像の指示

### 4. 痛み② `--dangerously-skip-permissions`
- **スライドタイトル**: ほったらかすと時々主人に牙をむいてくる AI
- メッセージ: 手放しで99%は問題ないが、ホスト環境を壊されることがある

- 種別: 課題提示

### 5. コンテナで囲めば安全か
- **スライドタイトル**: じゃあ Docker コンテナで囲めば...?
- メッセージ: コンテナ運用にも別の痛みがある + そして、コンテナでも防げない問題がある
- 内容:
  - たしかに、ホスト環境を壊されるリスクは消える
  - しかし、別の痛みが現れる
    - 開発に必要なツールが揃っていない → Dockerfile を自分で盆栽する手間
    - 必要な道具が増えるたびに毎回イメージをビルドし直す手間
  - コンテナでも防げない問題がある
- 種別: 既存策の検討①
- ビジュアル: 箇条書き中心 (絵文字は使わない)

### 6. コンテナの本質的限界
- **スライドタイトル**: コンテナで守れるのはホストのファイルだけ
- メッセージ: コンテナの FS 分離はホストのファイルを守るが、情報流出系のリスクには対策にならない
- 内容: **実害シナリオ** を文章 (箇条書き) で示す — Brave 検索 API キーを環境変数で渡したコンテナで Web 検索 → 結果に PI → AI が PI に従い API キーを外部に POST → 「持っている秘密は漏れる」
- 種別: 既存策の検討② (核心の問題提起)
- ビジュアル: 文章 + 結論カード (Mermaid シーケンス図は採用しない。図にすると視線が左右に往復して読みづらい)
- 口頭補足: PI は完全には防げない (Brave Search 結果や閲覧した Web ページに PI が紛れる可能性は排除しきれない)

- **スライドタイトル**: 使い方

### 10. HeartGarden の機能
- **スライドタイトル**: HeartGarden の 5 つの機能
- メッセージ: HeartGarden を使うと、安全と利便が同時に手に入る
- 内容 (**抽象的な恩恵を 5 つ並べる**。実現方法 = Bifrost / egress-proxy / Guardrails の話は 10 枚目に譲る):
  - ホストとコンテナのファイルシステムが分離される (Podman)
  - AI が API キーを知らなくても認証ができる
  - プロンプトインジェクションが検知できる
  - アウトバウンドのリクエストを記録・監査できる
  - mise 標準搭載 & 開発ツールはコンテナを消しても残る → 毎回 Dockerfile を再ビルドしなくていい (5 枚目の痛みの回収)
- 種別: 解決策の恩恵 (中心思想キャッチは 11 枚目まとめで初登場&回収)
- ビジュアル: 5 つのカードレイアウト (アイコン + 一言)。安全系 4 つと利便系 1 つを色分けすると視認性が上がる。**実現主体 (Bifrost / egress-proxy など) はこのスライドには出さない**

### 11. アーキ全体図 — 入口 / 出口 / 鍵分離

- 種別: 解決策の全体像
- ビジュアル: `HeartGarden/docs/heartgarden-architecture-v3.png` を `slides/heartgarden/assets/architecture.png` にコピーして利用する。または再描画した Slidev コンポーネント版

### キーメッセージの強調

- 1 枚目タイトル + 11 枚目「まとめ」を控えめにし、各論のスライドで個別のインパクトを出す方針に変更
- 9 枚目「HeartGarden の 5 つの機能」は、5 つのカードを大きく配置してインパクトを出す
- 図解中心、テキストは最小限 (1 スライド 1 メッセージの徹底)

### 9 + 10 統合の判断は実装時に

- 現状は 9 (恩恵リスト) と 10 (アーキ全体図) を独立スライドにしている
- 9 が「何が嬉しいか」、10 が「どうやって実現しているか」を担うので、別スライドの方が役割は明確
- ただし実装してリズムが悪ければ 1 枚に統合する余地はある (アーキ図に恩恵を吹き出しで添えるなど)
- どちらを採用するかは、Step 3-C で実装したスライドを通して見て判断する
